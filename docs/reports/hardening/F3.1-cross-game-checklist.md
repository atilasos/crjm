# F3.2 Cross-Game Hardening Checklist (Dominorio + Atari Go)

Date: 2026-03-19  
Scope: deterministic hardening scaffold for the currently integrated tutor pipeline games.

## 1) N1..N5 consistency checks

Use this checklist in each F3 hardening run, with artifacts saved in JSON.

| Check ID | What to verify | Dominorio | Atari Go | Pass rule |
| --- | --- | --- | --- | --- |
| N-C1 | Level mapping consistency (V1 level to legacy/search profile) | `v1-adapter.test.ts` | `v1-adapter.test.ts` | All level-mapping assertions pass |
| N-C2 | Monotonic strength tendency (N+1 vs N) | `baseline:dominorio` ladder T1 | `baseline:atari-go` ladder T1 | No regression vs previous baseline > 5 p.p. |
| N-C3 | Time budget progression | `baseline:dominorio` T2 by level | `baseline:atari-go` T2 by level + monotonic steps | p50(N+1) >= p50(N) in most steps and within configured budget |
| N-C4 | Legal move reliability by level | `baseline:dominorio` T3 | adapter + logic tests | 0 invalid moves in deterministic checks |
| N-C5 | Stability/repeatability | `baseline:dominorio` T4 | adapter deterministic fixtures | Divergence does not increase vs previous run |

F3.2 status:
- Atari Go `N-C2` and `N-C3` are now measured in JSON at `artifacts/atari-go-baseline/latest/baseline.json`.
- Known failures remain expected in early runs; track directional change (`failedPairs`, `failedLevels`, `monotonicSteps`) instead of binary PASS/FAIL only.

## 2) Pedagogical observable checks

Apply these checks to both games in tutor mode and preserve counts/rates in JSON artifacts.

| Check ID | Observable | Signal |
| --- | --- | --- |
| P-O1 | Feedback brevity | `explainText` non-empty and <= 160 chars |
| P-O2 | Actionability | Message includes a concrete next action (verb + target) |
| P-O3 | Reason transparency | Message includes at least one causal marker (threat/space/parity/liberties/endgame) |
| P-O4 | Threat visibility | `criticalThreats` present when immediate tactical risk exists |
| P-O5 | Post-game review usefulness | `turningPoints` or quick review items produce 1..3 items |

## 3) F3 run protocol (small and repeatable)

1. Run `bun run hardening:f3.2`.
2. Read `artifacts/hardening/f3.2/latest/summary.json`.
3. Inspect game baselines:
   - `artifacts/dominorio-baseline/latest/baseline.json`
   - `artifacts/atari-go-baseline/latest/baseline.json`
4. For each failed check, classify as:
   - expected-known (existing baseline weakness), or
   - regression (new or worse).
5. Record deltas in a dated report before changing heuristics.

## 4) Exit criteria for extending beyond F3.2

Proceed to the next hardening increment only when:
- cross-game adapter checks stay green,
- Dominorio ladder artifacts keep being generated,
- Atari Go ladder artifacts keep being generated with stable schema (`nC2`, `nC3`, `ladder`, `t2ByLevel`), and
- pedagogical observables are still measured in machine-readable output.
